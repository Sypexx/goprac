## Что это

Приложение для фиксации измерений в коровниках: показатели микроклимата и животных,
отчётность, инвентаризация. Ключевые требования: **RFID-метки** и **оффлайн-режим с выгрузкой**.

## Стек

- **Frontend:** `frontend/` — Vite + React 19 + TypeScript. Dev на `:5173`, прокси `/api` → `:8080`
- **Backend:** `backend/` — Go (net/http, роутинг Go 1.22+ с параметрами путей), драйвер `pgx/v5`
- **БД:** PostgreSQL 18, локальная, служба `postgresql-x64-18`. Подключение через `backend/.env`
  (переменная `DATABASE_URL`, шаблон в `backend/.env.example`, пароль НЕ в git)
- **Git:** https://github.com/Sypexx/goprac, ветка main

## Запуск

```bash
cd backend && go run .      # терминал 1 — API + статика на :8080
cd frontend && npm run dev  # терминал 2 — dev-сервер на :5173
```

Открывать `http://localhost:5173` (dev) или `:8080` (прод-сборка из `frontend/dist`).

## Схема БД (MVP реализован)

Миграции идемпотентны, применяются при старте сервера: `schema.sql` → `seed.sql` → `comments.sql`
(пакет `backend/db`, embed). Комментарии к таблицам видны в DBeaver/pgAdmin.

- `users` — сотрудники (**admin**, **user**, **zoo**). Пароли хешируются через bcrypt. Токен — base64("id:username:role").
- `group_types`, `groups` — типы групп (Коровники, Склады) и иерархия групп
- `object_types` — **иерархия типов с parent_id**:
  Организация → Строение → Коровник/Конюшня; Животное → Корова/Лошадь. Флаг `group_flag`
- `objects` — **единый реестр экземпляров с иерархией parent_id**:
  Организация → Строение → Коровник → Животное (решение: одна таблица + FK вместо «таблица на тип»)
- `object_identifiers` — RFID/бирки/чипы (у объекта может быть несколько, UNIQUE по типу+значению)
- `object_groups` (m:n), `object_history` — принадлежность группам и аудит перемещений
- `measures` — показатели (Температура/Влажность/Вес/Надой), тип **instant/balance**
- `measure_to_object_type` — какие показатели у какого типа объектов
- `measure_values` — сырые измерения. **`client_uuid UNIQUE` = идемпотентная оффлайн-синхронизация**
  (повторная отправка не создаёт дубль, `ON CONFLICT DO NOTHING`), `author_id` проставляется из токена

Сиды: **3 организации** (АО Агрохолдинг, ООО Новый, ООО Хатасский Свинокомплекс),
строение «Главный корпус», коровники №1/№2 в нём, коровы (Зорька, Бурёнка, Милка) в Коровнике №1
с бирками `TAG-*`, показатели привязаны к типам.
Пользователи: `admin/admin123`, `user/user123`, `zoo/zoo123`.

## API

- `GET /api/health`
- `POST /api/login` → токен в заголовке `X-Auth-Token`
- `GET /api/objects` — **всё активное дерево объектов** (parent_id/parent_name); с `?group_id=` — фильтр по группе
- `GET /api/object-types` — типы объектов с parent_id (для каскадного выбора)
- `GET /api/groups` — список групп
- `GET /api/measures?object_type_id=` — показатели типа объекта
- `GET /api/measure-values?object_id=` — последние 50 измерений объекта
- `POST /api/measure-values` — одно значение `{client_uuid, measure_id, object_id, value, measured_at, device_id}`
- `POST /api/sync` — пакетная выгрузка `{values: [...]}` → `{inserted, skipped}` (skipped = дубли по uuid)

**Только admin** (`X-Auth-Token` + роль admin):
- `GET/POST /api/admin/objects` — список/создание объектов (с `parent_id`, биркой)
- `PUT/DELETE /api/admin/objects/{id}` — обновление / архивирование
- `GET/POST /api/admin/users` — список / создание пользователей (логин, пароль, роль)
- `GET/POST /api/admin/measures` — список / создание показателей (с привязкой к типам через `type_ids`)

**admin + zoo:**
- `GET /api/reports/measurements?object_id=&measure_id=&from=&to=` — история измерений
- `GET /api/reports/summary` — статистика (объекты, измерения, сегодня)

## Фронтенд

`frontend/src/App.tsx` — экран логина + три панели по роли:

- **AdminPanel** — статистика + вкладки: **Объекты** (фильтр по типу, создание с каскадным
  выбором родителя по иерархии типов, архивирование), **Пользователи** (создание с ролью),
  **Показатели** (создание + привязка к типам объектов)
- **UserPanel** — сайдбар-дерево иерархии (организации → строения → коровники → животные,
  раскрывающиеся узлы), хлебные крошки, карточка объекта (ввод измерения + история +
  дочерние объекты плитками). Оффлайн: записи копятся в `localStorage` (ключ `offline_queue`),
  при появлении сети автосинхронизация на `/api/sync`, статус онлайн/оффлайн в шапке.
  UUID генерируется с fallback для не-secure контекстов (HTTP по сети).
- **ZooPanel** — отчёты: выбор объекта/показателя/периода, таблица измерений с автором
